# ROADMAP v5 — Template lifecycle, delivery visibility, export

**You are done with v5 when** a merchant logs into the portal and sees their own templates listed separately from five — now six — shared starters; creates a template from scratch by choosing a name, bill type and skeleton; opens a starter, edits it, and can only Save As, landing a clean-break copy named `(1)` because the name was taken; opens their own template, renames it and saves in place, leaving one list entry; deletes a template that never issued a bill and gets its name back; is refused deletion of one that did; archives a third, sees it in the archived view with its name still reserved, and restores it as `(n)`; picks a different default for receipts and for tax invoices, and sees `POST /v1/bills` honour the tax-invoice one and reject a receipt template id with `422`; sees which broadcasts failed and resends one; exports their bill history and finds a committed audit row for it — and a second merchant's every resource is **404** at every `/portal` endpoint, `Bill.snapshot` and `Bill.layoutSnapshot` are byte-identical to before this phase, and **every v1, v2, v3 and v4 test is still green**.

**Task-ID convention.** `S-` continues as the schema prefix (S-1…S-9 across v1/v2/v4) and `X-` continues as the cross-phase regression prefix. `A-` continues for the one task that completes v4's auth surface rather than starting a new one. New workstreams take unused letters — `F-` for template lifecycle (fork-on-write is the theme of every task in it), `I-` for the industry starter template, `R-` for resend and delivery reporting, `E-` for export. `C-`, `G-`, `M-`, `T-`, `U-` and `V-` are **not** reused: they appear in Phase-3 source comments (`templates.service.ts` cites C-1/C-2/C-3, G-1, M-3, T-6) and reusing them would make a grep across roadmaps ambiguous.

**Sequencing note.** I-1 is deliberately placed early, immediately after the schema work it depends on, per the decision to build the utility template first once documentation is complete. It has no dependants, so it can also be cut or moved without disturbing anything else.
